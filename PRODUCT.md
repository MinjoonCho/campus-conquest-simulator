# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated: Python standard-library local server with static HTML, CSS, and JavaScript so the tool works offline without a frontend build step.

## Users

- The primary user is a competition developer repeatedly configuring and comparing Campus Conquest bots on a local machine.
- Codex and Claude use the same system through noninteractive CLI and JSON interfaces.

## Product Purpose

Campus Conquest Arena runs official-engine matches, measures timing, compares models across seeds and sides, and makes every result reproducible. Success means a person can launch and understand an experiment quickly while an agent can perform the same operation without UI-specific logic.

## Positioning

One official match core serves both human visual inspection and machine-driven evaluation; strict competition runs and flexible research timing remain clearly separated.

## Operating Context

The tool runs offline on a MacBook or a remote development PC. Users register local Python or C++ bot commands, run single matches or series, inspect aggregate results, and replay individual games on a 15 x 15 map.

## Capabilities and Constraints

- Uses the provided official engine and replay schema as the source of truth.
- Supports strict, observe, and off timing modes with a separate safety timeout.
- Browser UI binds to loopback by default.
- Core runtime uses Python's standard library.
- The interface must remain useful at desktop and narrow laptop/mobile widths.

## Evidence on Hand

- Official PDF rulebook at `깃발대항전_게임규칙서.pdf`.
- Official development tools at `yk-development-tools.zip` and extracted under `vendor/official/`.
- Real run, match, timing, and replay data generated by Arena; the UI must not invent performance claims.

## Product Principles

- Official parity before convenience.
- Make experiment state visible, not implicit.
- Human and agent workflows share one core.
- Risky or non-official settings are unmistakably labeled.
- Dense operational information remains calm and scannable.

## Accessibility & Inclusion

Keyboard-operable controls, visible focus, sufficient contrast, reduced-motion support, semantic labels, and layouts that remain usable at 320px width.
